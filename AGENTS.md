# Правила работы с проектом

- Сохранять существующее поведение приложения.
- Выполнять миграцию небольшими этапами.
- Одна feature — один отдельный этап.
- Не менять Supabase-контракты без отдельного задания.
- Не выполнять production write-команды.
- После изменений запускать format, analyze и test.
- Не смешивать рефакторинг и изменение функционала.
- Не удалять FlutterFlow-зависимости, пока они используются.
- Каждый этап должен быть пригоден для отдельного Git-коммита.
- При неопределённости сначала документировать, а не угадывать.
